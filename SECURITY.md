# Security Policy

## Supported versions

Only the latest tagged release is supported.

## Reporting a vulnerability

Do not open a public issue for credentials, personal data exposure, unsafe file handling, command execution, or dependency vulnerabilities. Use the repository's **Security → Report a vulnerability** workflow so the maintainer can review the report privately. If private vulnerability reporting is not yet enabled, contact the repository owner through their GitHub profile without including sensitive details in a public issue.

## Data handling

The intended workflow processes authorized local video files on the user's machine. It does not require API keys or remote speech recognition. Generated media, subtitles, reports, and evidence files must remain outside Git history.
